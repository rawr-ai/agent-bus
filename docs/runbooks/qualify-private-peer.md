# Qualify the hosted peer fixture

Exercise the hosted peer projection and its pinned direct host against a disposable Bus and synthetic identity. This does not qualify ChatGPT, a real upstream identity provider, the permanent connection or a live Bus. The [connections reference](../architecture/connections.md) describes the trust boundary.

## Before you start

Use a development worktree, the pinned Bun and Fluree on `PATH`, `gh` with access to the private host repository, and `openssl` for a disposable local certificate. Put the pinned Bun first on `PATH` for nested commands too, and check `bun --revision` against the [selected host cohort](../platforms/mcp-openapi.md#direct-host-and-http-admission); an absolute parent executable alone does not select nested bare `bun` commands. Older host runtimes are not a supported fallback. The tests start a supervised disposable Fluree instance and never load live provider credentials or a live ledger.

The Events consumer uses the genuine host package's exported types, not copied interfaces. The full developer installation has an explicit private-artifact prerequisite. Obtain the exact approved archive through its release owner's protected handoff, or through a normal authenticated GitHub release download once that artifact is published. A selected unpublished candidate is not evidence that its release tag exists. Set `APPROVED_HOST_ARCHIVE` to that authorized local archive, then from the checkout root:

```sh
mkdir -p dist/private-artifacts
cp "$APPROVED_HOST_ARCHIVE" dist/private-artifacts/mcp-openapi-2.1.0-a1ca308.tgz
HOST_ARCHIVE="$PWD/dist/private-artifacts/mcp-openapi-2.1.0-a1ca308.tgz"
printf '%s  %s\n' 90ac182ec316eaff54b787573ca076aea5bd98e346d2f6290945f05a4c244cce "$HOST_ARCHIVE" | shasum -a 256 -c -
bun --no-env-file install --frozen-lockfile --ignore-scripts
```

Bun owns package installation and declarations through the relative `file:` dev dependency; no script extracts into `node_modules`. Keep the archive ignored and out of Git. A cold `bun install` cannot acquire the private release by itself, and an anonymous public checkout cannot complete this full developer install without authorized artifact access. CI needs separately authorized private-repository access; the public repository's ordinary token does not imply it. Never put credentials, transient signed URLs or absolute local paths into the manifest or lockfile. The builder separately checks the approved archive, installed raw host entry and host-relative required runtime, then bundles that runtime into the private host module. The native Bus runtime is not upgraded. The review manifest distinguishes the raw entry checksum from the transformed host checksum. These steps do not select a live bundle or change service configuration. *Rehearsed 2026-11-15 with the selected candidate handoff; this is not publication or anonymous installation proof.*

The selected host speaks the modern wire contract only. The qualification-only helper sends `server/discover` and the required protocol metadata, asserts the complete-result/server-info envelope, and then checks the independent tool or Events carrier. It qualifies the host's JSON-response path, not general SSE-client interoperability. Legacy SDK `initialize` is not relabelled as modern client proof. The intended saved hosted client remains a separate deployment check; fixture transport changes do not establish its compatibility.

## Run the fixture

1. Run the local identity, Events callback and real-Bus peer tests:

   ```sh
   bun --no-env-file test test/private-web-identity.test.ts test/private-web-watch-authority.test.ts test/private-web-events.test.ts test/private-web-peer.test.ts test/wake-observation.test.ts
   ```

   Expected: provider and independent per-principal grant checks pass; distinct synthetic principals with the same conversation correlation and one principal with distinct correlations join and exchange mail. Reciprocal foreign inbox refusals preserve each pending message for its rightful reader, and reconnect recovers the same holding. The cross-principal takeover is an intentionally authorized transfer, not an isolation proof; takeover and ambiguous-result checks pass. Prepared watch authority is private, durable and stable for an unchanged full holding; unknown/foreign tickets and usable contradictory metadata refuse. Preparation and Events capture consume no mail, while ordinary read/publish still require their normal correlation. Continuing authority survives a later read, mute or inactivity but refuses a stale holding or revoked grant. Complete checkpoints, deterministic timestamps and occurrence identity are checked independently of callback delivery. *Rehearsed 2026-11-14 with the released dependency and disposable fixtures.*

2. Build one private review bundle in an existing private directory, then supply
   that exact output to the HTTP fixture:

   ```sh
   PRIVATE_BUNDLE=$(bun --no-env-file scripts/build-private-peer.ts "$HOST_ARCHIVE" /absolute/path/to/private-output)
   bun --no-env-file scripts/qualify-private-peer.ts "$HOST_ARCHIVE" --bundle "$PRIVATE_BUNDLE"
   ```

   Expected: the builder checks the archive/raw entry and host-relative runtime imports, bundles with normal Bun resolution, and rejects a remaining bare runtime import. The fixture verifies the selected manifest and output checksums without rebuilding or modifying that directory; its printed host checksum identifies the bytes exercised. It uses synthetic API-key and provider proof over modern HTTP, with independent tool-result schema checks. The host's `bus_publish` and `bus_peers` output schemas name the same properties as the serve's, including `wake`. Distinct, omitted and empty conversation metadata stay request-local, and deliberately reversed resolver completion preserves each invocation's metadata and owner. A revoked grant is rechecked on a previously authorized correlation. A waiting conversation receives another's publication; a publication to a never-joined address returns its `wake` notice through the host; wrong subject and grant are refused. Invalid hidden native arguments return the host's safe `isError` result before tool execution. An injected post-publication response loss produces one stored message, not a dropped-transport proof. Fixture services stop and temporary files are removed. Omitting `--bundle` retains a standalone build into the fixture's disposable directory, not evidence about another bundle. *Rehearsed 2026-11-15 against one selected corrected bundle, including explicit reuse and the Bus-cap headers-only early refusal.*

3. Qualify that same private review bundle after relocation:

   ```sh
   bun --no-env-file scripts/qualify-private-bundle.ts "$PRIVATE_BUNDLE"
   ```

   Expected: the qualifier verifies the selected three-file bundle's manifest and checksums, copies it away from the checkout, checks there are no `node_modules` ancestors, and starts its actual entry sequentially with fresh `HOME`, minimal `PATH`, synthetic private configs and a local HTTPS provider. It explicitly provisions disposable watch state through the bundled initializer, never creates it implicitly on startup, and refuses existing-state reinitialization. Events-enabled startup configurations with omitted, explicit `false` and explicit `true` diagnostics complete the same unauthenticated OAuth challenge. Only the enabled mode emits a parsed host POST admission record and consumer enabled control; neither disabled mode emits either diagnostic prefix. A tools-only startup with the flag true emits host diagnostics but no consumer prefix and requires no watch state. That cold-start control does not independently inspect the authenticated disabled catalogue; preparation omission also rests on the unchanged service conditional. Stderr capture is bounded and evaluated after owned-process shutdown. A separate modern HTTP fixture invokes the relocated real service with two provider subjects and protected grants, exercises owning preparation, direct Events authority callbacks, grant failure/recovery, ownership refusal and preserved unread mail. It intentionally omits the public Events transport; step 4 qualifies that bridge. Its API-key-to-synthetic-token adapter is not actual OAuth evidence. Supervised children and temporary files are removed. The working-tree source is not attested by this review manifest. *Rehearsed 2026-11-15 against the same selected corrected bundle as the HTTP and Events lanes.*

   The emitted `agent-bus-hosted-guidance-wire-v1` record is explicitly intermediate: count its guidance assertions as qualified only when the supervised child exits zero and all later parent checks succeed. This is a synthetic API-key modern-HTTP check, not real OAuth, SSE, public Events transport or ChatGPT skill-loading evidence. *Rehearsed 2026-11-15.*

   The relocated fixture also compares the served skill manifest and every file against an independently enumerated authored tree, checks both directories and link resolution, and retrieves the whole skill progressively under the configured HTTP limit. It checks a mapped caller without conversation correlation can use a session-free lookup while an ownership call refuses. On macOS, a verified sandbox profile denies the development tree, the named Codex, Claude and agent skill-cache paths, and the original bundle to relocated children; on other platforms the fixture establishes cwd and HOME relocation, not source denial. *Rehearsed 2026-11-15 against the selected candidate bundle.*

4. Exercise the optional Events program through the same exact built host:

   ```sh
   bun --no-env-file scripts/qualify-private-events.ts "$HOST_ARCHIVE" --bundle "$PRIVATE_BUNDLE"
   ```

   Expected: the fixture verifies archive/raw entry pins and the built host seal, then uses public native OAuth registration, consent and PKCE against a synthetic upstream provider. OAuth helpers do not bootstrap a legacy MCP session; discovery and Events requests use the modern wire envelope. The actual hosted preparation tool proves ownership through normal tool metadata and native observation. Production callbacks then accept the prepared arguments without Events metadata, preserve subscription identity across same-argument refresh and a fully joined restart, and refuse foreign/altered tickets or usable contradictory metadata. Ordinary tool ownership stays unchanged. Discovery-time grant denial remains exact host `not_found` with no subscription callback. Signed notices and payload schemas contain only the address; ticket/binding canaries stay out of callbacks, diagnostics, public history and protected host storage bytes. Existing captured-notice retry after an owner read/restart, account-only unsubscribe after grant loss, requested lease expiry and independent native-access expiry remain exercised. A 120-ID checkpoint exceeds 4 KiB and restores the exact published ID set and canonical binding/cursor/ID-set digest after the old host has fully exited. `--case checkpoint` and `--case native-expiry` select only those discriminators; neither replaces the full fixture. The native-expiry case requests a longer lease, checks its required native-expiry clamp, an expired-bearer modern-discovery 401 and a fresh-authorization delivery control; it does not isolate native rechecking from that required persisted lease expiry. Callback admission uses an isolated test-only DNS/TLS dial redirect, not an actual public callback destination. Supervised children and temporary files are removed. *Rehearsed 2026-11-15 with synthetic native OAuth and disposable Bus/Fluree against the same selected corrected bundle as the other two lanes.*

   This fixture also checks the skill through OAuth with an unmapped authenticated principal, a mapped principal without correlation, and invalid authentication, audience, Host and Origin. It verifies a successful read after refusals. It runs the selected relocated peer's tool and Events composition with the selected host, using a fixture-owned identity map, authority and host configuration; its higher test-only HTTP rate does not replace step 3's shipped-limit traversal. The actual production entry and configuration are the separate step 3 lane. The same macOS source-denial control applies here; other platforms do not establish that denial. *Rehearsed 2026-11-15 against the selected candidate bundle.*

5. Keep fixture, source adoption and client outcomes separate. Building or qualifying a review bundle does not select it for an installed service. Follow [deploy](deploy.md#when-a-hosted-peer-is-connected) only under a separately authorized deployment. Qualify skill discovery and use through the existing Agent Bus integration in a new client conversation; a fixture or published resource does not establish client activation. The existing [actual-client check](../platforms/mcp-openapi.md#direct-host-and-http-admission) exercised fresh OAuth and two conversations against a disposable ledger; it did not exercise this skill-publication candidate. Before claiming automatic hosted wake, the intended client must actually discover and subscribe to `mail.wake`, accept its verified callback, and cause the rightful conversation to read its own mail. A callback receipt, an unrelated model turn or shared-history lookup is not that chain. A late notice may correctly lead to an empty read, and retries may repeat the same notice; they do not permit another conversation's inbox or bypass ordinary tool authorization. *Unverified: actual-client skill activation and live Bus activation have not been rehearsed by this procedure.*

## If it fails

Check the pinned runtime and fixture output. A checksum mismatch refuses before host import; obtain the intended artifact rather than relaxing the check. Enabled Events with incompatible storage/key, missing or damaged watch authority, or unsupported native authorization must refuse rather than silently fall back to tools-only operation; omission of Events is the intentional disabled mode. Never delete watch state to recover from a refusal or capacity bound: preserve the evidence and use an explicitly scoped operator recovery. Identify any fixture process by its own supervisor before stopping it; never kill by a shared pattern or touch the installed Bus. For installed-service recovery, see [recover](recover.md).
