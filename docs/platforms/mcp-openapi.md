# Owned direct-tool MCP host

Observations of the checksum-pinned direct-tool host in disposable private fixtures and with an actual ChatGPT client. They do not authorize exposure of a live Bus; its current trust rules are in [connections](../architecture/connections.md).

## Direct host and HTTP admission

- **Verified in development, 2026-11-13:** the `mcp-openapi` 1.1.0 release at commit `ba7941117038b079371a65ea6ca29727382be03c` passed both [private peer fixtures](../runbooks/qualify-private-peer.md) on Bun 1.4.4. The archive was built from `b6598398a4ca16118c9321ed76b19e42db3d2c4e`, which has the identical tree `29e50685664f3cb36d5fc1451cccdf50b113c127` (archive SHA-256 `d16821e6e327dbab807811fd07a0db5884adef41a922d838648ca021e778c0d8`, entry SHA-256 `8c3e4aa9c172a1caf107e352aee8e9676c98ff2ff0b27003655cb0508d77b939`). The exact-host HTTP fixture checked the text-only missing-correlation refusal, complete text and structured results including escaped Unicode over 16 KiB, concurrent wait and publish, ownership, grant refusal and one stored publish after an injected lost result. The relocated bundle fixture checked two synthetic principals, grant failure and recovery, ownership refusal and preserved mail. These disposable fixtures do not establish actual OAuth or client behavior or activation.
- **Verified live, 2026-11-11:** in ChatGPT Work with GPT-6.1 Sol Light, a fresh browser OAuth consent connected the existing app to a sealed peer built from agent-bus source `3e69bee6796cbee0467747226116f2eab852bd1b`, with Bun 1.4.4 and the owned `mcp-openapi` 1.0.0 host from source `da738cbd9e8b0d29a4e2d7dbbb379971b23ae719` (host module SHA-256 `78ac81acc5bb47bd001efd00d504d2adc42857263d21d32ffc3ddfc57b166642`). Against a disposable ledger, two conversations under one owner joined separate addresses; each sent and read mail with a native fixture peer, the second was refused when consuming the first's inbox, and the first retained ownership and pending mail when revisited. Both could see shared history, including a multiline body retrieved by the second. All 16 tools were discovered; peers, join, owned addresses, publish, read, history and leave were exercised. This is an observation of that composed client, host and peer, not proof that every client supplies conversation metadata. It does not establish a new-chat takeover, compaction, restart, token refresh, revocation, automatic wake, large-result UI limits or live-ledger operation. The [frame](../frames/hosted-chatgpt-peer.md#actual-client-check-2026-11-11) records the scope.
- **Verified in development, 2026-11-11:** the metadata-preserving `mcp-openapi` 1.0.0 artifact from source commit `da738cbd9e8b0d29a4e2d7dbbb379971b23ae719` passed the [peer fixture](../runbooks/qualify-private-peer.md) with Bun 1.4.4 and the official MCP SDK 1.32.2. Synthetic conversation metadata reached the direct tool resolver over HTTP; two callbacks overlapped while one waited, and a request above the configured body cap was refused before resolver invocation. The archive SHA-256 was `4c95d202370fa3af4515a5993a659d733682c22f7f95e8bfc4ad834518ca3f4a`. This does not establish actual ChatGPT or provider behavior.
- **Verified in development, 2026-11-09:** the owned `mcp-openapi` 1.0.0 tarball identified below ran `serveTools` on Bun 1.4.4+38afee6c8. With the official MCP SDK 1.32.2 as client, closed input and output schemas and read-only annotations appeared on all four tools. Both text and structured carriers preserved the complete result. The escaped synthetic page measured 23,369 logical UTF-8 JSON bytes and 58,385 HTTP response-body bytes, not counting HTTP headers. This is not a ChatGPT wire or model-context limit.
- **Verified in development, 2026-11-09:** with `maxConcurrentWork: 1`, the direct host refused a five-request reconnect burst with HTTP 503 after a downstream disconnect, while the facade still owned one unanswered Bus exchange. Reads resumed when it settled. Native HTTP request close is not relied on to cancel upstream work.
- **Unverified:** provider grant refusal and revocation timing, post-restart token refresh, large-result UI limits, live-ledger operation and the unexercised tools. The separate development fixture uses synthetic provider proof and an API key at the loopback transport only; that fixture does not demonstrate OAuth.

The owned artifact is `mcp-openapi-cdb182c1695db3bb.tgz`, SHA-256 `cdb182c1695db3bba023f6b85dadb2d3dbe63a9f15713e69bce9e512e311d428`, from the Breeze archive's owned vendor package. It is staged privately, not included in this repository. The [frame](../frames/private-chatgpt-web-mcp.md) gives the precedent and approval boundary.
