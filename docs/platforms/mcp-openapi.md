## ChatGPT plugin source and update routes

- **Verified live, 2026-11-27 UTC; Codex CLI 0.164.0 (save and read) and 0.171.0-alpha.13.2 (independent read):** two signed-in installations read the same existing Personal definition at `1.0.3`, with one app and one skill. In the `created-by-me-remote` marketplace, `plugin/read` resolved the exact backend ID in `pluginName`, **not** the package slug. A first-party app-server `plugin/share/save` of the verified expanded package used that existing ID, omitted sharing settings and returned the same ID. Fresh remote reads on both installations showed `1.0.4`, the same app and skill, and the plugin enabled. A separate `plugin/skill/read` matched the selected root `SKILL.md` byte for byte; the existing authenticated hosted connector also completed a read. Neither check establishes the remote bytes of referenced files or automatic skill loading in a conversation. This was an update to one Personal definition, not a migration to GitHub or a save against a workspace directory.
- **Read in tagged Codex 0.164.0 source, 2026-11-27 UTC:** the [published plugin protocol](https://github.com/openai/codex/blob/rust-v0.164.0/codex-rs/app-server-protocol/src/protocol/v2/plugin.rs) distinguishes backend `version` from materialized `localVersion`; `plugin/list` with `forceRefetch: true` requests a fresh remote catalogue. The [save handler](https://github.com/openai/codex/blob/rust-v0.164.0/codex-rs/app-server/src/request_processors/plugins.rs) requires sharing support and rejects `discoverability` or `shareTargets` alongside an existing `remotePluginId`. An unknown ID or a 404 in another workspace does not establish that the original definition is absent.
- **Observed live, 2026-11-16 UTC; ChatGPT client build unavailable:** one existing MCP-origin Personal plugin's management menu offered **Download plugin ZIP**, **Upload new version** and **Delete**; that menu did not show **Edit Plugin**. A same-definition ZIP update was accepted, and the existing plugin identity and saved connection remained visible. This is one inspected definition and UI, not a claim that every Personal plugin has the same controls or that another editing route is impossible.
- **Documented, reviewed 2026-11-27 UTC:** for a GitHub-managed workspace marketplace, [OpenAI's sync guide](https://help.openai.com/en/articles/20001504-importing-and-syncing-plugin-marketplaces-from-github) identifies the configured repository, path and ref as the source. Daily sync is enabled by default for new marketplaces; **Sync now** requests an update from that source. Refreshing the displayed list is not a source sync. The Personal save above did not exercise a workspace sync.
- **Documented and reviewed, 2026-11-16 UTC:** the [Plugin Creator guide](https://learn.chatgpt.com/docs/build-plugins#edit-an-existing-plugin) describes conversational editing when creation, Plugin Creator and edit access are available, but does not establish that route for the inspected MCP-origin Personal definition. [Plugin help](https://help.openai.com/en/articles/20001256-plugins-in-chatgpt) and the [workspace GitHub guide](https://learn.chatgpt.com/docs/enterprise/plugin-management) describe workspace administration; the [Codex CLI](https://learn.chatgpt.com/docs/developer-commands#codex-plugin) describes client marketplace operations, and [directory submission](https://developers.openai.com/plugins/deploy/submission) is a publication path whose ZIP cannot contain app references (`apps` / `.app.json`) or lifecycle hooks. Across those authoring, administration, distribution and CLI sources and the [changelog](https://learn.chatgpt.com/docs/changelog), no documented GitHub migration preserving the existing Personal cloud definition was found. That is a bounded source review, not proof that such a route cannot exist. Recheck when Personal source/update support, the UI or official guidance changes.
- **Documented, 2026-11-16 UTC:** the [workspace GitHub guide](https://learn.chatgpt.com/docs/enterprise/plugin-management#move-an-existing-plugin-to-github-management) says that moving an eligible existing workspace plugin using a matching name and `pluginId` preserves its ID, sharing and workspace settings, but subsequent updates come from GitHub and archive replacement is no longer available. A failed invalid update keeps the last working version; the guide says to correct the GitHub source and sync. Restoring prior source content and syncing is an inferred recovery, not a rehearsed rollback. Removing a marketplace entry leaves its workspace copy marked no longer in source, whereas deleting the marketplace deletes its imported plugins. The guide states no exemption for a plugin moved using `pluginId`; treat deletion as capable of deleting that existing plugin. To change the importing admin, it instead describes reimporting with the same source, path and ref. An existing plugin managed by a different GitHub source cannot use the documented move method. These documented workspace rules do not establish Personal migration, live migration success, skill carry-over or continued connected-app authorization; check the resulting skill, account access and client separately.
