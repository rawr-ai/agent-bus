# Bun

This page records Bun behavior the bus and its development tools depend on. The installed versions and recheck register are in [platforms](README.md); the runtime binding is in [interfaces](../architecture/interfaces.md), and its procedures are in [install](../runbooks/install.md) and [deploy](../runbooks/deploy.md).

## Runtime and TOML

- **Verified in a development checkout, 2026-11-02:** Bun 1.4.4+38afee6c8 trims the opening newline of a TOML multiline literal string, unlike Bun 1.3.14. The native agent adapter renderer's literal oracle and parity tests passed with the newer parser. The eight existing generated Claude adapters lose one leading body blank line, not foundation text. Recheck the literal oracle and generated-body parity after changing Bun. This is development evidence, not live deployment evidence. See the [upgrade frame](../frames/agent-bus-toolchain-upgrade.md).
- **Verified in a development checkout, 2026-11-02:** invoking `bun run` through an absolute Bun 1.4.4 executable did not itself select that executable for a script's bare `bun` command: with Bun 1.3.14 first on `PATH`, the script printed 1.3.14. Set the child `PATH` to the selected executable as well, and check its identity; do not infer script runtime from the parent command. Recheck this behavior on a Bun upgrade.
- **Read in code:** the new installer writes a launcher invoking the selected executable with `--no-env-file`; `package.json` binds its accepted version. Changing a shell's `PATH` or a global Bun link does not change a launcher already written with an exact executable path.
- **Verified during release packaging qualification, Bun 1.4.4+38afee6c8:** `--no-env-file` does not suppress the working directory's `bunfig.toml`; its `preload` can execute for a file or stdin invocation. An explicit `--config` replaces that lookup. The release launcher and verifier name the sealed empty `app/bunfig.toml`, preserving the caller's cwd without its Bun preload. The installer uses `/dev/null` for inline validation. A home-directory config was not loaded in the decoy measurement. Source launchers retain the working-directory exposure. Recheck the decoy qualification after changing Bun or these invocation paths; [release packaging](../frames/release-packaging.md#adjustments-after-the-testing-design-review) records the finding, and `scripts/qualify-release.ts` exercises the relocated launcher against a decoy cwd.
- **Verified on a disposable launchd installation, 2026-11-02:** the selected Bun 1.4.4 executable loaded the canonical development source and ran `serve` through the installed launcher. An old Bun 1.3.14 hook communicated with the upgraded server, and a candidate hook communicated with the restored old cohort. The source, frozen dependencies and executable were restored together; Fluree, credentials and configuration were unchanged. The same cycle passed from the durable versioned runtime location. These are macOS rehearsal results, not live activation or actual Claude model-wake evidence; the [upgrade frame](../frames/agent-bus-toolchain-upgrade.md) records their limits.
- **Observed live, 2026-11-02:** both machines ran `serve` and the hook on Bun 1.4.4+38afee6c8 from the versioned runtime location `~/.local/share/agent-bus/runtimes/bun-1.4.4/bun`, named in the managed launcher. The `serve` LaunchAgent's arguments were the launcher and `serve`, and the plugin hook still ran `~/.local/bin/agent-bus claude-wake`. The Bun on `PATH` stayed 1.3.14 on both machines, as intended: other tools use it, and agent-bus doesn't. The CLI worked under `env -i`, and an actual idle Claude session woke on each machine. A hook already waiting before the change kept its old runtime until it rearmed. The previous runtime was retained for rollback.
- **Observed live, 2026-11-11:** both installed launchers and running servers now bind Bun 1.4.4+38afee6c8 copied inside their immutable release, not the earlier shared runtime path. The existing viewer on one installation binds the same release runtime. Per-surface agreement is installation evidence, not proof that every already-running hook or session adopted new code or guidance; [deploy](../runbooks/deploy.md#deploy-a-packaged-release) states the live-client proof and remaining limit.
