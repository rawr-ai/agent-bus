# Frame: project orientation without a private briefing

This candidate frame studies project identity and one-step orientation inside the [turnaround](coordination-turnaround.md). Current addresses and membership are documented in [messaging](../architecture/messaging.md); related concerns are [topics](turnaround-topics.md) and [bulletins](turnaround-bulletin.md).

Status: discovery facet of the single orientation vertical, not a separate team or a decision to add a project table. DRA: Codex lead; shared model and composed orientation are owned by the parent frame. Mode: co-framing; object: solution.

## What and why

A joining participant needs the project's concerns, members, current orientation and relevant owners together. Today project membership is inferred from naming habits and origin metadata. The owner said projects might be needed and requested discovery and the whole product loop, not an automatic schema commitment.

In are project identity, explicit association, topic/member discovery and a composed onboarding result. Foreground the newcomer recovering the real preview handoff without a director's briefing. Exterior are company directories, new authorisation roles, automatic membership inferred solely from a path and a catch-all project topic.

Compare a first-class project identity with scoped topics plus a small explicit directory. Prefer the latter if it satisfies the same newcomer job with fewer independent states. A new noun does not earn its storage or API by itself.

## Hard core and assumptions

1. Project identity is explicit and survives clones, aliases and machine-local paths; inference is labelled rather than silently accepted.
2. Membership, topic subscription, activity and responsibility are different relationships.
3. One onboarding operation returns coherent orientation, with currentness and missing state explicit.

Assume more than one concern and more than one repository can belong to a project. Canonical IDs, association defaults and the comparison verdict remain open until real-team discovery. Do not expose private consumer examples in the public record.

## Adoption and falsifier

Before rollout, agree a fixed newcomer job and record its current briefing steps. After rollout, an unbriefed real participant finds the right project, concerns, members and current bulletin and identifies who owns the next action. The existing coordinator checks the answer, not the implementation author alone. If a directory over scoped topics performs equally well, drop the extra project mechanism. If the newcomer still needs the same individual briefing, iterate before claiming adoption.
