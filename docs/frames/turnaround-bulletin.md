# Frame: server-owned current orientation

This candidate frame covers a built-in bulletin under the [turnaround](coordination-turnaround.md), with [projects](turnaround-projects.md), [topics](turnaround-topics.md) and [activity](turnaround-activity.md) as related decisions. Current message history remains in [messaging](../architecture/messaging.md).

Status: proposed facet of the single orientation vertical, not a separate team or a renewed convention pilot. DRA: Codex lead; shared model and composed orientation are owned by the parent frame. Mode: co-framing; object: solution.

## What and why

A newcomer or returning participant should receive the current orientation without searching for a supposedly authoritative message. The server owns currentness and replacement. A running participant receives an ordinary delivery when it changes; a join or explicit read obtains the current value.

In are current project/topic orientation, provenance, version, review/expiry information and deterministic replacement. Foreground late-session discovery and skill/state updates reaching their intended audience. Exterior are ranked self-selection, subjects or reply links as replacement authority, recurring moderators and bulletin text as permission to execute historical tasks.

A saved query over ordinary messages is a useful retrieval technique but is not this product feature: it leaves designation and replacement semantics with the caller. A one-off broadcast does not orient late participants. The earlier pilot offers interpretation evidence, not a reason to repeat the same retrieval convention.

## Hard core and assumptions

1. Each accepted scope has one explicit current bulletin; history and concurrent replacement do not make callers guess which wins.
2. The setter/convener rule is an explicit workflow contract for trusted actors, not inferred from a newer message.
3. Currentness, expiry and unavailable orientation are visible; an expired bulletin is not silently treated as current instructions.

Assume permanent skills and project instructions remain separate owners of durable guidance. Project-versus-topic layering, atomic version rules, join compatibility and inactive-session catch-up need a coherent decision with the other feature frames.

## Adoption and falsifier

Record the current skill/state rebriefing job before rollout. After an approved deploy, a real late participant receives the current bulletin at onboarding and a running participant receives an actual update without a personal reminder or search coaching. Include replacement and expiry in maintained server tests, then measure correct real interpretation and rebriefing episodes. If the same update still requires a direct briefing, or ambiguous currentness survives, the feature is not accepted.
