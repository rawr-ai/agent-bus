# Public query containment

2026-11-01. Temporary capability-withdrawal decision and qualification, following the separate public response projection in [bus-design-query](bus-design-query.md). Current contracts belong to [interfaces](../architecture/interfaces.md#bus_query), trust rules to [connections](../architecture/connections.md), and operational activation to [deploy](../runbooks/deploy.md#public-query-containment).

## Decision

Keep the `bus_query` name, input schema and annotations, but return one fixed declared `LedgerError` for every otherwise schema-valid call. Refuse before parsing, reading head or a requested commit, or calling any store operation. Retain `Ledger.select` for compatibility with the same unconditional refusal in both implementations. No environment bypass, historical exception, empty-success response or fallback to a weaker query is permitted.

The director accepted this bounded containment after independent review and platform/runtime consultation. It is reversible through a separately qualified replacement, not a conclusion that useful native-policy queries are impossible. The prerequisite missing from the proposed grammar was reliable effective-governance evidence, not more syntax filtering. A parser that confines datasets and predicates cannot by itself ensure that hidden facts do not affect public rows.

Separate owner consultation confirmed working native owner-authentication and read-only query scopes in another deployment. That prior art establishes caller identity and action authority, not per-field private-data noninterference. Its owner supported temporary refusal here and a separately qualified public-only dataset/client as a successor option. No private project identifiers or credentials are part of this record.

The exact refusal is:

> Public SPARQL queries are disabled while the public-data boundary is being qualified. Use bus_history or bus_peers.

No credential, server configuration, installed service, stored JSON, ownership check or cursor is changed. Private reads, presence, search, append and delivery remain. `bus_history` and `bus_peers` are useful existing tools, not semantic replacements for historical graph queries, aggregates or whole-thread traversal. Their existing full-text behavior is not newly qualified for noninterference by this change.

## Hostile governance proof

The preceding qualification used disposable authenticated Fluree 4.2.4 servers, fresh short-lived scope-only credentials, synthetic ledgers and an independent public-only oracle. A missing bearer received HTTP 401. The credential had no subject, identity or policy-selection claim. No running bus ledger or production credential was used.

The attack ledger declared private `bus:json` a subproperty of public `bus:body` under locked RDFS. A permitted-looking aggregate over Presence subjects and `bus:body`, requesting `# PRAGMA reasoning: none`, still depended on private cardinality. The independent oracle was authored directly from the proposed public contract, not generated by the candidate filter. It held the same public facts and aligned commit counts.

| Private values | Public-only count | Hostile historical count | Hostile head count |
| --- | --- | --- | --- |
| 0 | 1 | 1 | 1 |
| 1 | 1 | 2 | 2 |
| 3 | 1 | 4 | 4 |

The hostile snapshot was tested at `t=2` after head advanced to `t=3`. Every response was HTTP 200 with `hasMore:false`. An unrestricted private-predicate count returned 0, 1 and 3, confirming that the oracle detected intentional exposure. Missing reasoning headers/blocks did not imply that reasoning was absent.

Additional probes distinguish missing evidence from impossible mechanisms:

| Probe | Result | Conclusion |
| --- | --- | --- |
| Ordinary config SELECT under required stored deny | Zero visible rows while locked reasoning remained active; tracking reported enforcement | An empty config query is not proof of absent config |
| Locked config without the hiding policy | Eight visible config rows | Correctly pinned config SELECT can expose settings, but visibility depends on governance |
| Pinned policy-unfiltered admin export with the same synthetic credential | Empty before config was written; hidden reasoning/default locks present afterwards, unchanged by synthetic reindex | Privileged export is a real possible evidence source, not a completed effective-governance receipt |

The installed version's documentation and independent source/runtime review distinguish stored configuration from active server policy defaults and token resolution, mutable external schema/policy sources, and the configuration under which existing full-text arenas were built. No supported continuous effective-semantics attestation was established. This is a counterexample to grammar plus requested reasoning-none, not to a correct gate that rejects these snapshots or to a separately authorized native-policy design.

Version-exact source references: `ledger-config/README.md`, `ledger-config/writing-config.md`, `ledger-config/override-control.md`, `ledger-config/setting-groups.md`, `security/policy-in-queries.md`, `query/tracking-and-fuel.md`, `api/headers.md`, `api/endpoints.md` and `indexing-and-search/fulltext.md`. The platform owner records the promoted findings in [Fluree](../platforms/fluree.md#query-limits). Raw tool responses, private paths and credentials are deliberately not part of this public record.

## Implementation and verification

- `src/Ledger.ts` owns the fixed refusal. The MCP handler invokes it directly, without requiring `Ledger`; `src/Fluree.ts` and the test JSONL ledger also use it for the retained `select` capability.
- `test/public-query.test.ts` drives actual HTTP MCP with a sentinel store that records and fails every attempted operation. Across three negotiated protocol revisions, including text-only and structured-capable clients, 11 query forms times six commit selections produce identical tool errors, no structured result and zero store operations. Inputs include direct and aliased private predicates, nested EXISTS/count, federation, mutation, malformed and empty strings, large ASCII and multibyte strings, and omitted/historical/head/invalid/future commits.
- `test/public-errors.test.ts` calls the actual Fluree implementation directly against a hostile fake upstream. Refusal does not add any data request, including a head read, and never echoes the caller or upstream sentinel. Existing upstream-error tests still cover history and peers.
- Both backend suites retain select-refusal regression checks. Existing message projection, ownership, read/wait/history, cursor, restart and delivery regressions remain in the full check.
- The parser and its tests remain as inactive utility coverage; they are not on the public execution path and are not confidentiality enforcement. No platform upgrade is part of this change.

Verification on this candidate: `bun run check` passed typecheck, lint, all 250 tests (2,103 assertions, including real Fluree backend tests) and the documentation check (40 Markdown files). The run prepended an existing test-local Fluree 4.2.4 binary to `PATH`; it did not upgrade the global installation. Independent review found no material implementation issue and separately ran the 41 HTTP MCP/error tests (1,383 assertions); its historical-source wording correction was applied. No publish, merge or deployment is part of this qualification.

## Re-entry contract

Refusal remains until a reviewed replacement proves the exact public contract under all admitted semantics. A bounded successor can start with the working privileged-export evidence, rather than repeating the rejected inline-policy admission attempt. A broader native-policy design or independently maintained public dataset requires an explicit new authorization and design decision; neither is implemented here.

Acceptance must cover:

1. Complete, unfiltered, exact-snapshot governance and asserted-subject evidence, including unknown/per-graph settings, effective server defaults and token resolution. Missing, malformed, partial, unsupported or unreadable evidence refuses; empty config and missing telemetry are not receipts.
2. Policy, reasoning, datalog, external schema/policy sources and cross-ledger dependencies, including drift during evaluation and historical or partially indexed snapshots. Adding admin export to the runtime path is an explicit bounded implementation choice, not an implied fallback.
3. Public-only full-text corpus statistics, counts, ordering and truncation, including old arenas and reindex history. Current full-text configuration alone is insufficient.
4. Complete recursive syntax admission for the chosen language, including nested EXISTS, paths, type tests, functions, unknown forms and subject scopes, with no root-query-only parser presented as security.
5. Equality with independently authored public-only oracles across all admitted recipes, private existence/cardinality changes, historical commits, large cells and both MCP encodings, plus preserved operational and response-projection regressions.

There is no automatic reopen after a platform upgrade or an apparently clean snapshot. Every server fronting the shared ledger must receive the containment before it is claimed active. Rollback must retain the refusal; restoring the earlier SELECT implementation reopens disclosure. This commit alone proves no deployed state.
