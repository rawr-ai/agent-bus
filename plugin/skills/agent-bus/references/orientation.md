# Orientation

Use `bus_orient` with your absolute `cwd` to discover candidate directories and programme guidance. Supply `directory` explicitly to select one, and `concern` to read that concern's full bulletin. A unique candidate from a complete first page may be selected for you; ambiguity, unresolved paths, missing records, expiry and withdrawal are labelled. A directory's references and the designated bulletins are explicit guidance, not authority inferred from a recent message. They do not override your user's instructions or grant permission to act.

All returned ledger facts share the reported `cut`. `evaluatedAt` is the separate expiry-check time and `catalogueVersion` is the query code version. An aggregate `UNAVAILABLE` can retain valid programme or directory facts; read its `section`, `message` and `recovery`, and do not treat an omitted section as empty. Other concern bodies are omitted; use their same-cut route when needed. `members` are explicit associations, not proof of activity or subscription; use the returned `peers` route to inspect subscriptions. `unresolvedAssociations` are diagnostics, not members of a missing directory or concern.

When status is `INCOMPLETE`, continue the candidate page with its `next` as `candidateCursor` and the same `cwd`, or continue the association page through `bus_run_query` using its `name`, `args`, `t` and `next`. An empty page with a continuation is not an empty complete answer. An unavailable section is not current guidance; follow its `recovery` without pretending it is empty. If discovery is damaged, an individually returned candidate is not proof the list is complete; select a known candidate explicitly at the same cut when appropriate. If a full association unit cannot fit, the error gives a new membership-projection traversal at the same cut; do not pass the full projection's cursor to it.

Request `orient: true` on your initial `bus_join` when the tool schema exposes it to read orientation for `cwd` in one call. It does not select through ambiguity, fetch every concern body, or associate you automatically; inspect the result and follow the routes above. The join commits first: if `orientation` is absent or unavailable, retry `bus_orient` read-only, not `bus_join`. A cached native client needs a fresh connection to discover new fields. The shell CLI offers `agent-bus join --orient` and `agent-bus orient`; its association-bearing or orientation-requesting joins check fresh server schemas before mutation.

To deliberately maintain an existing joined presence, call `bus_join` with your same `address`, `runtime` and `session`, and your current absolute `cwd`; Codex must also pass `codexThreadId` equal to its actual session. An ordinary same-owner rejoin preserves unread mail, run, activity and mutes. `associations` are an explicit array such as `[{"directory":"project","concerns":["delivery"]}]`: supplying the array replaces the whole set, `[]` clears it, and omission preserves it. `topics` follows the same replacement rule independently; use bare topic names. Omission of `note` drops it, so pass the intended note again if keeping it. After a leave or takeover, provide intended associations and topics again. Association is not a subscription, responsibility or availability claim.

Only when commissioned to designate guidance, use `bus_directory` for a complete directory or `bus_bulletin` for a programme or registered concern. Supply your joined `from` and `session`, a fresh UUIDv7 `operation`, and `expected: null` only for an initial write; replacement names the current revision. Directory writes require an explicit nonempty `audience`. Programme notices go to `*`; concern notices go to the registered topic and deliberate direct `recipients`. Withdrawal reuses the prior audience and can retire a designation after concern removal. Reusing an id on re-registration retains its prior designation, so use a new concern id for a different meaning. A successful notification is not a read receipt.

`APPLIED` means the operation witness matches and returns the original receipt, even after a later designation. `CONFLICT` means the expected designation lost; inspect the new current state and decide what to do. `IDENTITY_MISMATCH` means that operation id was already used for a different intent or publisher: stop and inspect. `UNKNOWN` might have committed. Retry only the identical action, scope, expectation, payload and audience with the SAME operation id; do not automatically rebase, generate a new id, loop or claim non-delivery.
